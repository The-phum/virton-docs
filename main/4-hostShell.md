# **4.3 셸 (Shell)**

> VirtOn의 호스트 셸 기능은 관리자가 별도의 SSH 클라이언트(Terminal, PuTTY 등) 설치 없이 웹 브라우저에서 물리적 노드(Proxmox Host)에 직접 접속하여 명령어를 실행하고 시스템을 제어할 수 있는 강력한 관리 도구입니다.
> 

![호스트셸 메인 1](../_static/images/main/hostshell/host_shell1.png)

## 사용 전 확인사항

| **구분** | **내용** |
| --- | --- |
| **필요 권한** | Host Shell은 물리 노드에 직접 명령을 실행하는 고위험 관리 기능이므로 관리자 권한과 노드 셸 접근 권한이 필요합니다. |
| **접속 대상** | Proxmox VE 노드 중 접속할 대상 노드를 선택합니다. |
| **인증정보** | 접속 시 Proxmox 계정 비밀번호를 입력합니다. 비밀번호는 화면에 마스킹되며 제출문서에는 원문을 기재하지 않습니다. |
| **감사기록** | 접속 시도, 접속 성공/실패, 주요 관리 행위는 감사 로그 확인 대상입니다. |

## 4.3.1 실시간 노드 제어 (Web-based Terminal)

### 4.3.1.1 웹 기반 셸 접속

![호스트셸 메인 3](../_static/images/main/hostshell/host_shell3.png)

- **브라우저 터미널**: 별도의 소프트웨어 없이 웹상에서 즉시 호스트 서버의 셸 환경에 접근합니다.
- **실시간 동기화**: 물리적 서버의 터미널과 동일한 속도로 명령어를 입력하고 결과를 확인할 수 있습니다.

## 4.3.2 보안 및 편의 기능

![호스트셸 메인 2](../_static/images/main/hostshell/host_shell2.png)

- **비밀번호 입력**: 호스트(노드) 셸을 사용하기 위해서는 연결 시 Proxmox의 계정 비밀번호가 필요합니다. 보안을 위해 입력 시마다 매번 입력해줘야 합니다.
- **행위 기록**: 셸을 통해 수행된 주요 활동은 VirtOn의 **감사 로그(Audit Log)**에 기록되어, "누가, 언제, 어떤 노드에서" 작업을 수행했는지 투명하게 추적합니다.
- **안전한 세션 관리**: 브라우저를 종료할 경우 세션을 자동으로 만료시켜 무단 접근을 방지합니다.

## 4.3.3 문제 해결 방법

| **증상** | **확인 항목** | **조치 방법** |
| --- | --- | --- |
| 셸 접속 버튼이 보이지 않음 | 계정 역할과 권한 | 관리자에게 Host Shell 접근 권한 부여 여부를 확인합니다. |
| 인증 실패 | Proxmox 계정 비밀번호 | 비밀번호를 다시 입력하고, Proxmox 계정 잠금 또는 권한 상태를 확인합니다. |
| 터미널 연결 끊김 | 브라우저 세션, WebSocket 연결, 노드 상태 | 다시 접속하고 노드 온라인 상태와 네트워크 연결을 확인합니다. |
| 작업 이력 확인 필요 | 감사 로그 | 알림/감사 로그 페이지에서 행위자, 대상 노드, 접속 IP, 결과를 확인합니다. |
